## 一、结构梁 —— 完成

### 原状

`bimconv_build.py` 里梁是一条明确的死路：

```python
if et == "beam":
    raise Exception(u"梁为实验性类型，本次跳过（需结构梁系统/线型族）")
```

而 `mapping_rules.csv` 里**早就写好 4 条 BEAM 规则**（含中文"梁"层名）——
规则在等实现，实现一直没来。

### 关键判断：不需要结构梁族

原注释的理由是"需结构梁系统/线型族"。但**楼梯已经用 DirectShape 破了这个前提**
（`_stair_solid`：台阶剖面 + `CreateExtrusionGeometry`，全程不碰族）。

梁同理：平面图里的梁就是**一条中线 + 截面宽高**，沿中线挤出长方体即可。

### 实现（`bimconv_elements.py` 新增 `_create_beam` 一族）

| 细节 | 做法 |
|---|---|
| 几何 | 矩形剖面（长 × 梁高）在 (沿梁方向, 向上) 平面内，沿水平法向挤出 |
| **居中** | 剖面平面从起点偏移**半个梁宽**，使梁以**中线居中**（不是贴着一侧） |
| 截面 | 优先 `beam_width_mm`/`beam_height_mm` 字段；否则从 `type_hint` 解析 `200x400` / `250*500` / `200X400`；再否则默认 200×400 |
| **标高** | 落在**楼层标高**上（`doc.GetElement(level_id).Elevation`）<br>⚠️ 对比：既有的 `_create_stair` 完全忽略 `level_id`，几何建在 z=0 —— 那是它的既有缺陷，梁没跟着错 |
| 类别 | `OST_StructuralFraming`，取不到则回退楼梯类别（宁可进错类别也别丢构件） |
| 坏输入 | 端点为 NaN/inf/越界、长度 < `MIN_WALL_SEGMENT_LEN`、剖面有效边 < 3 → **抛异常记跳过**，绝不喂给 Revit |
| 安全模式 | **跳过**（与门窗楼梯一致：新几何不进"只出骨架"那个承诺） |

> **已知取舍（已写进代码注释）**：建出来的是**几何占位实体**（DirectShape），
> 不是结构分析构件 —— 没有结构材质、不参与结构计算、不会自动与柱墙连接。
> 要真正的结构梁，得载入结构梁族并改用 `NewFamilyInstance`。

### 测试

## 二、PDF / YOLO —— 先量后做，**结论是做不出来**

### 动手前先量

计划里写的是"复现 `_train/` 的 10 个权重，打通'只有 PDF 没有 CAD'"。我先量了模型质量：

| 权重 | 末轮 mAP50 | 轮数 |
|---|---|---|
| `floorplan_v1` | **0.000** | 38 |
| `floorplan_v3` | 0.179 | 122 |
| `floorplan_v4` | **0.318** | 150 |
| `floorplan_v5`（最新） | **0.262** | 150 |

**最新版 v5 比 v4 退化了。**

### 官方 val 实测（全 96 张 val，imgsz=1280）

```
                 Class     Images  Instances   Box(P)   Box(R)   mAP50   mAP50-95
                   all         96       1085    0.847    0.272   0.306     0.199
```

**精确率 0.847 但召回率 0.272** —— 它开火时多半是对的，但**漏掉 73% 的目标**。
在自己的验证集上用常规阈值（conf ≥ 0.35）**一个都检不出来**；
单个样本的真值是 18 个，v5@0.35 检出 **0** 个。

### 还有一条更硬的理由

模型只有 **5 个类别**（`door / window / column / stair / elevator`），
**不识别墙**，而且输出是**边界框**不是几何线。

**即使精度提上去，"PDF → 完整模型"也不成立** —— 墙是模型主体，
必须来自 DWG 的图层几何（`DWG翻模`）。PDF 光栅图里没有图层语义。

### 处理：删掉"假装能用"的工具，换成可复测的评估工具

我先写了一个 PDF 识别工具，跑完自检发现它把"0 检出"当正常结果输出 ——
**那就是在骗人**。已删除，改为：

**`tools/floorplan_model_eval.py`** —— 权重质量客观评估

```bash
<workbuddy-python> tools/floorplan_model_eval.py --data _train/ds5
```

- 按 IoU≥0.5 贪心匹配算 TP/FP/FN，多阈值扫描（0.05 / 0.15 / 0.25 / 0.35）
- 主判据用训练记录的 mAP50；记录不到才现场跑 `ultralytics val`，
  且**明确标注数字来源**（"训练记录" vs "本次实测"）
- 内置可用门槛并给结论：`≥0.70 可用` / `≥0.50 边缘可用` / 否则**不可用**
- 附带一个**验证过可用**的能力：`--raster 图纸.pdf` 把 PDF 首页导出为 PNG
  （PyMuPDF 栅格化这一环没问题，有问题的是检测模型）

实测输出：

```
训练记录 mAP50 = 0.2622
结论: **不可用** —— 未达到可用门槛。**不要**基于它做识别入口 ——
      需要补数据/改训练，而不是改代码
```

### 要打通这条路，缺的是什么

| 缺 | 现状 |
|---|---|
| **数据** | ds5 只有 383 张训练瓦片 / 96 张验证；目标又是很小的符号（单个框约占图宽 2~3%） |
| **训练** | mAP50 0.26~0.32 是明显欠拟合；且**版本在退化**（v5 < v4），说明训练过程本身没收敛好 |
| **墙的类别** | 现在 5 类全不含墙。就算补齐上面两条，也只能做"符号识别"，仍不能出完整模型 |
| 代码 | **不缺** —— 栅格化、推理、匹配、评估都已跑通 |

**结论：这是数据与训练问题，不是代码问题。** 所以交付物是一个
**可复测的判据**，而不是一个看起来能用、实则检出率为 0 的入口。
