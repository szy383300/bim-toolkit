## 二、真正做完了什么

### 2.1 命令分档（桥侧）

**改前的真实安全状态**：整座桥的安全开关**只有 `allow_execute_code` 一个布尔量**，
而它只管 `execute_code` 一条命令。剩下的 34 条——**包括 `delete_elements` 这种不可逆删除、
`save_document` 这种可覆盖任意路径的写**——**没有任何策略约束**。

新增 `COMMAND_TIERS`（`bridge_core.py`）：

| 档 | 条数 | 内容 |
|---|---|---|
| `read` | 17 | `ping` / `get_*` / `query_elements` / `batch_count` / `run_report` / `get_quantities` / `list_steps` / `debug_walls` / `get_wall_geo` |
| `write` | 16 | `create_*` / `set_parameters` / `set_selection` / `set_material` / `save_document` / `dwg_to_model` / `apply_step` / `reset_view` / `export_view` |
| `dangerous` | 2 | `execute_code`、`delete_elements` |

`POLICY_TIERS`：`safe`=read / `build`=read+write / `dev`=全开。

### 2.2 策略闸门（唯一分发点）

闸门装在 `process_command` —— 它是**唯一**的命令分发点（只读命令直接进来，
写命令经 ExternalEvent 后也汇到这里）。被拒时：

- 写入**审计**：`{"event":"denied","cmd":...,"tier":...,"policy":...}`
- 写日志 `DENIED cmd=... tier=... policy=...`
- 回一个**能照着修**的错误：点名档位、当前策略、允许的档，以及改哪个文件

**顺序细节**：先判"命令是否存在"，再判策略。否则打错命令名会被报成"未分类档"，
把"你写错了"和"策略不允许"两种完全不同的情况混为一谈。

**fail-closed**：已注册但**未分档**的命令在**任何**策略下都被拒。
新增命令忘了进分档表时，宁可拒绝也不要静默放行。

### 2.3 配置向后兼容

`mcp_bridge_config.json` 新增 `policy` 字段：

```json
{ "policy": "dev", "allow_execute_code": true }
```

配置里**没写** `policy` 时，按旧的 `allow_execute_code` 推导（`true`→`dev`，`false`→`build`），
已有部署行为不变。未知的 policy 值会被忽略并 WARN。

### 2.4 `ping` 回报策略档 —— genbuild 开建前就能拒绝

`do_ping` 现在返回 `policy`。`genbuild/engine._stage_ping` 拿到后立刻判断：

```
如果 policy != dev -> raise BuildError（带完整修法）
```

**为什么这个设计重要**：genbuild 的配方会先**清场**（删 14 个类别的构件）再建。
若等到第一条 `execute_code` 才被拒，那时场已经清完、模型已经被破坏。
现在它在 `ping` 阶段、**模型一个字节都没动**的时候就停下来了。

### 2.5 两关新的机械化测试

本项目吃过三次"两份清单不一致"的亏（部署排除表 / 按钮清单 / 测试清单），
所以这次直接把它们钉死：

| 关 | 内容 |
|---|---|
| **第 7 关** | 解析 `bridge_core.py` 源码，断言 `COMMAND_TIERS` **恰好**覆盖 `COMMAND_HANDLERS`：不漏、不多、不重叠。**并自测**该校验器真能报错（改坏源码喂进去） |
| **第 8 关** | 在测试台桩环境里 **exec 真实的 `bridge_core.py`**，断言策略矩阵的行为；再断言 genbuild 在 `build`/`safe` 下开建前拒绝、`dev` 下放行 |

> 两个都要有：前者防清单漂移，后者防逻辑写反。

## 五、怎么用（运维视角）

### 场景 A：要用 genbuild（当前配置）

```json
{ "policy": "dev", "allow_execute_code": true }
```

### 场景 B：不用 genbuild，只要常规自动化

```json
{ "policy": "build" }
```

→ `execute_code` / `delete_elements` 被拒；`create_walls` / `set_parameters` 等照常。
**genbuild 会在 `ping` 阶段报错并告诉你怎么改回来。**

### 场景 C：只读巡检 / 给外部 AI 只读权限

```json
{ "policy": "safe" }
```

→ 全部写操作被拒，只能查。

**改完必须重新点一次 Revit 里的 MCP Bridge 按钮**（配置在 `start()` 时读入）。

被拒时审计里会留痕，可据此排查：
