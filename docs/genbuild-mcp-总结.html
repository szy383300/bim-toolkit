一、总体架构：AI 如何控制 Revit

核心思路：AI 不直接逐条调用 Revit API，而是产出声明式 YAML spec，由 gen_build 引擎按固定管线批量执行；每一步可 dry 预检、可幂等重跑、构建完自带 expect 数量验收，另配只读探针脚本做几何级复核。

五、验证体系（三层防线）

① dry 静态校验（0 成本）

python -m genbuild.cli xxx.yaml --dry：spec 校验 + 桥 ping。开洞越界、墙段过短、层数不符等 6 类问题在动 Revit 之前拦截。

② expect 数量验收（自动）

spec 写 expect 计数，构建尾 accept 逐项核对 got vs want，不符退出码 4。防"静默少建"。

③ 专项几何探针（只读）

_verify_*.py 经 execute_code 查询真实模型：包围盒、标高阶梯序列、楼梯 Z 连续性、材质 RGB、贯通检查，输出 JSON 供 AI 解读。塔楼阶梯 y=1480→3080→4680→6280→7880（每级精确 1600）即由此证实。

环境坑速查（详见 skill）

  • 同文件并行 Edit 竞态 → 串行 + Grep 复核
  • 桥闪断 → 健康窗口立即跑正式任务
  • Bash shim 故障 → 切 PowerShell，输出落盘防 UTF-16
  • genbuild 须以 E:\bim-toolkit\mcp 为 cwd 运行

六、DWG 翻模：现状盘点与接入方案

已就绪桥端「DWG翻模」V2.4（.dwg/.dxf → dwg_to_dxf.py（CAD COM / LibreDWG 兜底，ODA 工具已在 _tools\ODA）→ dwg_to_json.py → model_plan.json → 预览 → 确认写入）； 已就绪引擎 _stage_dwg + 骨架墙置换 supersede（≥95% 覆盖才删，防误删）； 已就绪骨架墙探针产物 genbuild\_dwg_walls_probe.json（折线墙段 + 高度已能读出）； 待做以下四步，等你发 DWG 后按序执行：

序行动项状态
1转换链 headless 化：AI 侧直接跑 dwg_to_dxf.py → dwg_to_json.py 批处理出 model_plan.json（不经 Revit 按钮交互），先出图元统计报告（墙线/柱/门窗可识别数）第一步
2识别质量评估：拿 model_plan.json 与 _dwg_walls_probe 对拍，确认墙段合并、柱/门窗映射规则（mapping_rules.csv）覆盖度，必要时调规则待图
3两段式建模：spec 配 dwg 段建骨架 → 墙/板/门窗精修段叠加 → supersede 置换删骨架，逐标高推进待图
4DWG 项目探针：复用 _verify_* 模式写 _verify_dwg 项目脚本（墙位对拍 DWG 坐标、开洞审计、验收矩阵），交付 RVT + 对照表待图

风险提示：DWG 图层命名不规范（墙线不在 WALL 层、无闭合多段线）会显著降低识别率；转换链依赖本机 CAD COM 或 LibreDWG，第一次跑需实测转换耗时与字体/编码问题。

七、结论

「AI ↔ Revit」控制链路已成型并经 6 个真实项目验证：设计意图 → YAML/生成器 → dry 拦截 → 27s 级批量构建 → 自动验收 + 几何探针 → RVT 交付，全流程幂等可重试。能力面覆盖轴网、墙体（含墙型/材质）、楼板、楼梯、栏杆、坡屋顶、门窗开洞、结构柱与骨架置换；DWG 翻模的桥端与引擎侧接口均已就位，只待图纸进入第一步转换评估。
