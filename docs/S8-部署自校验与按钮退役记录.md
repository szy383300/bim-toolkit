## B. S8：版本留底 + 部署后自校验

### B3 —— 版本写进**安装目录**

改前只写 `pyrevit-bim-panel\version.txt`（仓库内），**安装目录什么都没有** ——
而桌面四个 `.bat` 全部指向安装目录，光看它根本不知道装的是哪一版。

现在 `deploy.py` 两处都写：

```
安装目录 version.txt : 20261001-180642  deploy  38d2c06  v2.0.0
仓库     version.txt : 20261001-180642  deploy  38d2c06  v2.0.0
```

格式 = `时间 + 短 git commit + extension.json 版本`。

### B5 —— 四份副本可区分

此前四份内容不同的副本**全都自称 v2.0.0**，版本号完全丧失标识作用。
现在每份安装目录都带 `version.txt`（时间戳 + commit hash），可精确区分。

### B4 —— 部署后自校验（逐文件哈希）

新增 `_verify_mirror(SRC, DST)`：**不看 robocopy 退出码**（它 0~7 都算成功），
只看实际落地结果 —— 逐文件 MD5 比对，报「缺失 / 内容不同 / 多余」三类问题。
排除表与 robocopy 的 `/XD /XF` **同口径**，另加 `version.txt`（部署时才产生）。

不一致时：**exit=1 且不打 git 标签**（不能让没落地的版本留下"已部署"痕迹）。

真实部署实测：

```
[4] 部署后自校验（逐文件哈希）
  [OK] 已装副本与仓库逐文件一致（72 个文件）
```

### 自校验器**本身**的自测（`selftest.py` 第 6 关）

一个"永远通过"的校验器毫无价值 —— 所以给它也写了测试。
`tests/test_deploy_selfcheck.py` 造 3 类差异，实测：

```

3) 内容不同          : ok=False ['内容不同: a.py']
4) DST 多文件        : ok=False ['多余（已装独有）: orphan.py']
5) 排除表生效        : bridge.token / mcp_audit.jsonl / version.txt /
                       __pycache__ / logs_archive 全部被忽略，不误报

```

已接入 `selftest.py` 成为第 6 关（不接入的测试会腐烂）。
