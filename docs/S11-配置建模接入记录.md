## 一、先解决一个架构问题

`genbuild` 是这套东西里设计最好的部分（YAML 配方 → 静态校验 → 发射桥命令），
但它**跑不进 Revit**：

| | genbuild 引擎 | Revit 2019 的 pyRevit |
|---|---|---|
| 解释器 | CPython 3 | **IronPython 2.7** |
| 依赖 | `PyYAML`（`genbuild/spec.py:18`） | **没有 yaml** |

所以按钮**不能** `import genbuild`。正确做法与 `DWG翻模` 完全一致
（那边也是把 ezDxf 的活丢给外部 CPython）：

> **按钮 = 前端**（选配方 / 干跑 / 确认 / 调子进程 / 回显日志）
> **引擎 = 外部 CPython 子进程**

按钮只驱动两条命令：

```
1) <python> E:\bim-toolkit\mcp\gen_build.py <配方.yaml> --dry     # 干跑
2) <python> E:\bim-toolkit\mcp\gen_build.py <配方.yaml>           # 正式构建
```

## 二、安全闸门：三段式（这是本节的重点）

翻源码时发现一个**必须让用户知情**的行为：

```
engine.execute(dry=False):
   _stage_ping      → ping
   _stage_takeover  → 文档守卫 / 另存
   _stage_wipe      → ★ 清场：删除 config.WIPE_CATS 里的类别，再重建标高
   ... 然后才开始建墙/板/楼梯/屋顶/门窗
```

`WIPE_CATS` 实测 **14 个类别**：

```
OST_Walls, OST_Doors, OST_Windows, OST_Floors, OST_Roofs, OST_Stairs,
OST_StairsRuns, OST_StairsLandings, OST_StairsRailing, OST_Lines,
OST_Grids, OST_GenericModel, OST_StructuralColumns, OST_Columns
```

即：**正式构建会先把当前文档里的墙/门/窗/楼板/屋顶/楼梯/轴网/柱删掉。**

所以按钮做成三段，而不是一个"开始"按钮：

```
【1】干跑     静态校验 + ping 桥；不通过就停在这里，模型一个字节都不动
【2】清场确认  弹出确认框，**点名本次实际会被删的类别** + 当前文档名 + 配方名
【3】正式构建  用户点「是」才执行
```

> **关键细节：清场类别表是"现读"的，不是硬编码。**
> 按钮通过一次极短的子进程调用 `from genbuild import config; print(config.WIPE_CATS)`
> 取回权威清单。这样引擎改了类别，按钮的警告**自动跟着变**，不会两边漂移 ——
> 本项目吃够了"两处清单不一致"的亏（部署排除表、按钮清单、测试清单都踩过）。

| `配置建模.pushbutton/icon.png` | 1365 B | 图标（`make_icons.py` 生成，`wrote=1 skipped=18`） |

### 路径怎么找

genbuild 引擎与 `buildings/` 在**仓库**里，不在扩展目录里（扩展装在 `%APPDATA%`）。
所以按钮目录下放了一份 `genbuild_config.json`：

```json
{ "repo_root": "E:/bim-toolkit", "python": "", "recipes_dir": "buildings" }
```

`python` 留空则按候选表自动探测（与 `DWG翻模` 同款思路）。
`repo_root` 找不到时给出明确的"请检查 genbuild_config.json"提示，而不是崩掉。

### IronPython 2.7 兼容

无 f-string；`open(..., "rb")` + 显式 `decode`；子进程输出**重定向到文件**
（沿用 `DWG翻模` 的教训：管道缓冲会塞死）。

## 六、怎么用（给使用者）

1. Revit 里点 **MCP Bridge** 启动桥（必须，否则干跑会停在 exit=2）
2. 点 **配置建模** → 选 `E:\bim-toolkit\buildings\*.yaml`
3. 看干跑结果：
   - 有「问题」→ 改 YAML 重来，模型未被触碰
   - 通过 → 弹确认框，**逐条列出会被删的类别**
4. 点「是」→ 正式构建（后台跑，完成后回显日志尾部）
5. 日志落在 `%TEMP%\genbuild_run_<时间戳>.log`，引擎自己的日志在 `buildings\logs\`
