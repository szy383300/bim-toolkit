# 能否替换掉屋面「体量替身」？—— 实测结论（2026-10-02）

## 先给结论

| 问题 | 答案 |
|---|---|
| 能用参数化真屋面（`FootPrintRoof` / `ExtrusionRoof`）替代吗？ | **本机 Revit 2019 上做不到**。实测 **44+ 种组合全失败** |
| 那体量替身能做到多好？ | **已升级为「有正式类型名 + 正确类别」的 DirectShape**（本轮已实现） |
| 还有什么路？ | 只剩一条：**模板 .rvt + `CopyElements`**，代价是要手工做一次模板 |

---

## 一、先把 API 面枚举干净

`Autodesk.Revit.Creation.Document` 上**只有两个**屋面入口（用 `RevitAPI.dll` 直接反射枚举）：

```
NewFootPrintRoof(CurveArray footPrint, Level level, RoofType roofType,
                 out ModelCurveArray footPrintToModelCurvesMapping)
NewExtrusionRoof(CurveArray profile, ReferencePlane refPlane, Level level,
                 RoofType roofType, double extrusionStart, double extrusionEnd)
```

`RoofBase` 全谱系也只有 `FootPrintRoof` 与 `ExtrusionRoof` 两个类。

**没有 `NewRoofByFace`，没有第三个入口。** 所以"换一个 API"这条路本身就不存在 ——
问题只能落在"为什么这两个失败"。

---

## 二、实测矩阵：44+ 次，全失败

### `NewFootPrintRoof` —— 32 次全失败，错误恒定

| 变数 | 取值 |
|---|---|
| 标高 | 标高 1、屋面 |
| 轮廓 Z | `0`、标高高程 |
| RoofType | 全部 8 种（含"常规 - 400mm"基本屋顶） |
| 活动视图 | 平面视图（**已实测确实切过去了**，非之前那次失败的实验） |

→ **32/32 全部 `Value cannot be null.`**

这是 Revit **内部**的空引用，不是参数缺失 —— 桥的诊断也确认
"CurveArray/Level/RoofType 均已核验非空"。**改调用方代码解决不了。**

### `NewExtrusionRoof` —— 12+ 次全失败，错误是另一种

| 变数 | 取值 |
|---|---|
| 轮廓朝向 | 参照平面内（X=0）、垂直于参照平面（对照组） |
| 活动视图 | 平面视图、**立面视图**（"南"） |
| RoofType | 全部 8 种 |

→ **全部 `Invalid profile.`**

### 我修正了原实现的一个**真实错误**，然后仍然失败

枚举出的签名说明：轮廓必须**躺在参照平面内**。参考平面的构造是

```
NewReferencePlane(bubbleEnd=(0,0,0), freeEnd=(0,13000,0), cutVec=(0,0,1))
→ 由 Y 轴与 Z 轴张成，即 X=0 平面，法向沿 X（实测法向 = (-1,0,0)）
```

**所以轮廓必须写成 `XYZ(0, y, z)`（X 恒为 0）。**
而原 `GABLE_ROOF` 宏与我的第一版探针都写成了 `XYZ(x, 0, z)` ——
那是 Y=0 平面，**与参照平面垂直**，必然 `Invalid profile.`

**修正朝向后重试，依然 `Invalid profile.`** —— 所以朝向不是（唯一）原因。

> 这条修正本身仍有价值：它记录了一个**已证伪的错误假设**，
> 免得后人再往这个方向试一遍。

## 三、已实现的改进：给体量替身一个**正式类型**

在"参数化屋面做不到"的前提下，体量替身还有提升空间。实测两条：

| 试验 | 结果 |
|---|---|
| `DirectShapeType.Create(doc, name, ElementId(OST_Roofs))` | ✅ **可用**（建出屋顶类别的类型） |
| `ds.SetTypeId(<该类型 id>)` | ✅ **可用** |

**改动**（`mcp/genbuild/macros.py` 的 `GABLE_FREEFORM`）：
屋面 DirectShape 现在会挂上一个按坡度命名的类型。

实测结果：

```
屋顶类别元素: 1 个
  id=341044  class=DirectShape  族与类型=341045  名称=BIMT-双坡屋面-25度
```

**比之前好在哪**：以前它没有类型，在屋面明细表里只能归到"默认"；
现在能按 `BIMT-双坡屋面-25度` **分组统计**，属性栏里也看得到类型名。

**实现时踩的一个坑（已修）**：类型查找最初只用 `get_Name()`，
而该访问器在 `DirectShapeType` 上不稳 —— 会导致"找不到已有类型→每次构建都新建一个"。
改成 `Name` / `get_Name()` 两种都试。另经确认 `WIPE_CATS` **包含 `OST_Roofs`**，
类型每次构建本来就会随类别一起被清掉重建，**不会累积**。

## 四、其它思路逐条评估

| 思路 | 可行 | 原因 |
|---|---|---|
| **斜楼板**（`Floor` + 定义坡度） | ❌ | 类别仍是楼板 —— 那正是本次要修的原始缺陷，换汤不换药 |
| **体量 + 面屋顶**（Massing + Roof by Face） | ❌ | API 无此入口（已反射枚举，屋顶只有 2 个方法） |
| **可载入屋顶族**（.rfa） | ❌ | Revit 的**屋顶是系统族**，不能做成可载入族放进屋顶类别 |
| **`PostCommand` 驱动 UI** | ❌ | 会把屋顶命令弹给用户，草图仍需人画，不可无人值守 |
| **模板 .rvt + `ElementTransformUtils.CopyElements`** | ⚠️ **可以，但有代价** | 见下 |
| DirectShape（现状） | ✅ 已实现 | 正确类别 + 正确几何 + 正式类型名 |

---

## 五、如果一定要「真屋面」，唯一可行路线

**模板法**：

1. 人工在 Revit 里（或用 UI）建一栋含真屋面的样板，另存为 `_models/roof_template.rvt`
2. genbuild 在需要屋面时：`OpenDocumentFile(template, detach=True)` →
   取其中的 `RoofBase` 元素 → `ElementTransformUtils.CopyElements` 到目标文档 →
   按需要缩放/移动 → 关闭模板
3. 或者直接以该模板为起始文档建楼

**代价与风险**：
- 需要维护一份二进制模板，且模板一旦被 Revit 版本升级就不可逆
- 复制过来的屋面其标高、草图平面都是模板里的，**迁移到目标文档后需要重新绑定标高**
- 若目标文档的标高名/高程与模板不一致，屋面会错位
- 比现在的方案复杂一个数量级，收益是"能编辑坡度、能挂屋顶窗"

**我的判断**：以当前项目的使用场景（翻模出几何体量、做展示与核对），
**现方案（正确类别的命名体量）性价比更高**；模板法留作"确实需要参数化屋面"
时的升级路径。

---

## 六、一句话总结

**换 API 无路可换（只有 2 个入口，都已实测穷尽）；
换思路只剩模板法（可行但代价高）；
当前最优解 = 正确类别 + 正确几何 + 正式类型名的体量替身，本轮已落地。**

**44+ 次实测的价值不在"我试过了"，而在于它把"这条路不通"
从一句注释变成了可复现的证据** —— 顺带还纠正了一个真实的朝向错误。
