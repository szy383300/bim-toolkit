## 四、两个必须说清的边界

### 边界 1：**尺寸是固定的**

库里的屋面最大 **181.71 ㎡**，而且是它们原本所属建筑的形状。
新建筑的平面尺寸千变万化，**不可能正好匹配**。

而改尺寸需要改草图，`SketchEditScope` **在 Revit 2019 里不存在**（反射确认），
`ExtrusionRoof` 也没有 `GetProfiles()` —— 所以**没有可靠的程序化改尺寸手段**。

**结论**：现有模型能替代"**做一个含真屋面的通用样板**"，
但**替代不了"做出任意尺寸的真屋面"** —— 后者仍需人手建一次。

### 边界 2：**必须实现 `IDuplicateTypeNamesHandler`**

跨文档复制遇到同名不同类型时，Revit 会弹「重复类型」模态框，
**把桥的命令队列静默卡死**（我上一轮踩过，堵了 15 分钟，现象是
`ping` 秒回、`execute_code` 一直超时而 Revit 进程 `Responding=True`）。

```python
class UseDest(IDuplicateTypeNamesHandler):
    def OnDuplicateTypeNamesFound(self, args):
        return DuplicateTypeAction.UseDestinationTypes
```

`tools/harvest_roofs.py` 里已经带上了。**没有它，收割 39 个屋面会在第 2 个文件处挂住。**

## 五、实用结论

| 需求 | 能否用现有模型解决 |
|---|---|
| 要一堆现成的真屋面素材 | ✅ **已解决**，`roof_library.rvt` 39 个 |
| 要一个**尺寸正好**的真屋面 | ❌ 靠碰运气；仍需人手建一次 |
| 要任意尺寸的真屋面 | ❌ 未解决（2019 无 SketchEditScope） |
| 要有坡度的真屋面 | ✅ 库里 -19°~43° 都有现成的 |
| 要有体量的模型 | ✅ 库里另有 5 个 Mass 来源可继续收 |

**建议的用法**：把 `roof_library.rvt` 当成**素材库**——
新楼建完后，从库里挑尺寸最接近的屋面复制过来，`doc.Move` 摆到位置，
再人工微调（或接受这个近似）。这比"每次从零手工画"省事得多，
但**不等于全自动**。

## 六、踩到的两个技术坑（已修，记下来）

1. **`DB.Mass` 在 Revit 2019 不存在**（只有 `MassInstanceUtils`）。
   把它写进顶层 import，会让整个 `execute_code` 载荷**瞬间失败** ——
   表现是每个文件 0~1 秒返回 `None`。体量必须用 `OST_Mass` 类别收集。
2. **模态框不是"失败"**，桥的 `IFailuresPreprocessor` 管不了它。
   任何"无人值守"的跨文档操作都必须先想清楚会不会弹框。
