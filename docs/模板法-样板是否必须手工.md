# 模板法：样板必须手工制作吗？—— 不必（2026-10-02 实测）

## 直接回答

**不必。** 我原先说"模板法要手工做一份样板"，那个前提**是错的**。

**Revit 自带样例工程里就有真屋面**，而且可以**程序化地复制进我们的模型** ——
连"样板"本身都能自动拼出来。

## 二、`CopyElements` 能把它们搬进来 —— 实测可行

```python
ids = List[ElementId](); ids.Add(src_roof.Id)
opts = CopyPasteOptions()
opts.SetDuplicateTypeNamesHandler(UseDest())      # ← 关键，见下节
ElementTransformUtils.CopyElements(src_doc, ids, doc, Transform.Identity, opts)
```

实测结果：

| 源 | 复制后 | 类别 |
|---|---|---|
| `ExtrusionRoof` (243274) | `new_id=341155` class=**ExtrusionRoof** | 屋顶 ✅ |
| `FootPrintRoof` (724430) | `new_id=342057` class=**FootPrintRoof** | 屋顶 ✅ |
| `FootPrintRoof` (724430) | `new_id=342104` class=**FootPrintRoof** area=70.79㎡ | 屋顶 ✅ |

**真屋面，真类别，全程无人工。**

## 三、踩到的坑（很重要，会卡死整个桥）

**第一次尝试时 Revit 弹了模态对话框「重复类型」，把桥的命令队列堵死了 15 分钟。**

现象很有迷惑性：

```
ping          → 秒回（不碰 Revit API，照常响应）
execute_code  → 一直超时
Revit 进程    → Responding = True（看起来"正常"）
```

最后靠枚举窗口才看到真相：

```
3277714 | 重复类型          ← 模态框卡在这里
458888  | Autodesk Revit 2019 - [三层社区服务中心.rvt - 立面: 南]
```

**原因**：跨文档复制时，目标文档里已存在同名但定义不同的类型（屋面类型等），
Revit 默认弹框让人选。而桥的失败预处理器（`IFailuresPreprocessor`）**管不了模态框** ——
模态框不是"失败"，是等人操作。

**正解**：实现 `IDuplicateTypeNamesHandler`，由代码决定，**根本不弹框**：

```python
class UseDest(IDuplicateTypeNamesHandler):
    def OnDuplicateTypeNamesFound(self, args):
        return DuplicateTypeAction.UseDestinationTypes
```

加上它之后重测：**无对话框、无阻塞、一次成功**。

> 这是"能不能无人值守"的分水岭。没有它，模板法在自动化流水线里是**不可用**的 ——
> 它不会报错，它会**静默挂住**。

## 四、还没解决的部分（要说清楚）

复制过来的屋面带的是**样例的尺寸**，不是我们的：

| 项 | 样例给我们的 | 我们需要的 |
|---|---|---|
| 屋面面积 | 70.79 ㎡ / 173.14 ㎡ / 1592.58 ㎡ | 约 216 ㎡（18×12m） |
| 标高 | 自动重映射（实测落到 "2F"） | 屋面层 |
| 轮廓 | 样例的 | 我们的矩形 |

**能做的**：`doc.Move` / `RotateElement` 摆位置与朝向（简单可靠）。
**难做的**：改成任意尺寸 —— 需要改草图，而：

- `SketchEditScope` **在 Revit 2019 里不存在**（反射确认 `hasattr(DB, "SketchEditScope") == False`）
- `ExtrusionRoof` **没有 `GetProfiles()`**（实测 `'ExtrusionRoof' object has no attribute 'GetProfiles'`）
- `FootPrintRoof` 有 `GetProfiles()`，但直接改 `ModelCurve` 的几何属于"改草图"，
  在停用 SketchEditScope 的年代**没有官方入口**，风险高（本轮未继续试，避免再次卡死）

**所以现状是**：能拿到**真屋面**，但拿到的是**样例的形状**。

## 五、修正后的完整方案

```text
① 从 Revit 样例复制出若干个真屋面（不同尺寸/类型/坡度）
   —— 这一步程序化，用 CopyElements + IDuplicateTypeNamesHandler
② 把这些屋面存进我们自己的 roof_library.rvt
   —— 于是"样板"也是程序化拼出来的，不需要人画
③ 建楼时：挑尺寸最接近的样板屋面 → CopyElements 进目标文档 → doc.Move 摆位
④ 若尺寸差异大：在 ① 阶段就多收集几个不同尺寸的样例屋顶，提高命中率
```

**关键结论：连样板本身都不必手工制作** —— 可以用 Revit 自带的样例工程
程序化地"攒"出一份屋面库。

## 六、与现有方案的关系

| 方案 | 是真屋面 | 尺寸可控 | 无人值守 | 代价 |
|---|---|---|---|---|
| **当前：DirectShape 体量** | ❌（但类别正确 + 有正式类型名） | ✅ 任意 | ✅ | 无 |
| **模板法（样例复制）** | ✅ **是** | ⚠️ 只能取样例现成尺寸 | ✅（加 handler 后） | 需维护屋面库 |
| 手工做模板 | ✅ | ✅ | ✅ | 要人画一次 |

**建议**：把模板法作为**可选增强**，而不是替换当前方案 ——
当前方案尺寸任意、无外部依赖；模板法能给出可编辑坡度的真屋面，
但受限于"只能挑现成尺寸"。

**唯一还需要人做的事**：如果确实要**任意尺寸的真屋面**，
那仍然需要**手工建一次**符合该尺寸的样板 —— 这一条没有被推翻。
被推翻的只是"必须手工建一个通用样板"。

---

## 七、一句话

**样板不必手工做 —— Revit 自带样例里就有真屋面，`CopyElements` 能搬进来；
但"任意尺寸的真屋面"仍需人手建一次。**
顺带收获一条硬经验：**跨文档复制必须实现 `IDuplicateTypeNamesHandler`，
否则 Revit 会弹模态框静默卡死整条自动化链路。**
